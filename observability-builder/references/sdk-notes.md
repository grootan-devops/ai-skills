# SDK and framework notes

Known behaviour of SDKs, runtimes and frameworks that affects how a service meets this
standard, found while instrumenting real services. Each entry names the version it was seen
with. Versions move, so confirm an entry against the version you install before you rely on
it. Add entries when you find new behaviour, and drop them when a release fixes it.

How the loader writes exporter variables for SDKs that read them differently (Python's
timeout units, the `INSECURE` flag) is in [config.md](config.md#sdk-differences).

When the standard asks for something an SDK can't do, such as dropping a resource attribute or
a cardinality limit, ship without it and say so in the report. Don't patch an SDK's private
internals to get it: the patch breaks silently on the next upgrade, and the audit flags it
(`sdk-internal-patch`).

## Everywhere

| Topic | Behaviour | What to do |
| --- | --- | --- |
| Testing exports | In-memory and console exporters never open a connection, so they hide TLS, protocol, endpoint-path and timeout mistakes | Check once against a real receiver ([acceptance.md](acceptance.md#local-receiver)) |
| Resource detectors | SDKs add resource attributes of their own unless the module builds the resource: `telemetry.sdk.*` and, depending on the SDK, `host.*`, `os.*`, `process.*` or `service.instance.id` | Give every provider a resource built from the yml alone, per SDK below ([data-model.md](data-model.md#resource)). Where an SDK can't drop an attribute, report it. |
| `trace_flags` | SDKs that set the W3C random-trace-id flag write `03` for a sampled trace | Test bit 0, never the whole byte ([app-logs](signals/app-logs.md)) |
| HTTP client errors | Some clients put the full request URL, query included, into exception messages, e.g. on timeouts | Sanitize client exception messages before they reach logs or `exception.message` |
| Exemplars | Exemplars keep the measurement attributes that a metric view drops (OTLP `filteredAttributes`), so a raw `url.query` recorded on a metric leaves through the exemplar. Seen with the Quarkus 3.40 extension (OpenTelemetry Java 1.62). | When OTLP metric push is on, record only bounded attributes on OpenTelemetry metric instruments. Never pass raw URL, query or id attributes, even when a view drops them. |
| OneUptime recorder | Seen with OneUptime 14.0.x. Not published on npm: OneUptime serves the loader and recorder scripts, and the recorder loads with an integrity hash. It adds `tracestate: oneuptime=sid:<session>` to same-origin requests only when it loads after OpenTelemetry patched `fetch`. A Browser ingestion key refuses requests without `Origin`. | Load it through the same-origin proxy after the web SDK starts; pass the recorder bytes and `Origin` through unchanged ([rum](signals/rum.md)). |
| OneUptime recorder self-requests | Seen with OneUptime 14.0.11 and 14.0.17. The recorder treats every URL that starts with its `host` option as its own traffic (`isSelfRequest = url.startsWith(host)`). Behind a same-origin proxy `host` is the page origin, so an app that builds absolute same-origin API URLs (`https://app.example.com/api/…`) gets no session `tracestate` on them, and they drop out of the replay's network timeline; relative URLs are unaffected. | Set `host: location.origin + "/."`: the recorder's own URLs (`/./telemetry/session-replay/…`) resolve to the proxy routes, and absolute API URLs no longer match. It degrades to the old behaviour if the recorder ever normalises `host`. |
| OneUptime replay masking | Seen with OneUptime 14.0.x. In the default `MaskSensitiveInputsOnly` mode, `oneuptime-mask` hides text but not values typed into inputs; password, card, one-time-code, hidden and file inputs are always masked. | Put `oneuptime-block` on inputs that take personal data, or use a policy mask selector or `MaskInputsOnly`. |

## Node.js

| Topic | Seen with | Behaviour | What to do |
| --- | --- | --- | --- |
| Framework instrumentations | `@fastify/otel` 0.21, `instrumentation-nestjs-core` 0.69, `instrumentation-fastify` (deprecated) | `@fastify/otel` always adds an internal `request` span; the Nest instrumentation adds a start-up root span, two framework spans per request and a raw `url.full` with the query. | Leave them out: take the route from the framework (Fastify's `routeOptions.url`, Express's `req.route`) and let the app's wrappers span the handlers. Nest 12's 404 for the global prefix is itself a route (`*path`): treat it as `unmatched`. |
| HTTP and fetch spans | `instrumentation-http` 0.223, `instrumentation-undici` 0.33 | The server span takes `client.address` from `X-Forwarded-For` and carries no `error.type`; undici puts the raw query in `url.full` and ends its span only when the body is read; a fetch timeout gives `error.type="23"` and an exception span event. | Override `client.address` from the trusted-proxy resolver and `url.full` in the hooks; always read or cancel the response body; expect the span event next to the ERROR log record. |
| SDK start order | `sdk-node` 0.223 | Instrumentations patch modules loaded after `sdk.start()`; an `await` in the preload before it lets the app import first. | Start the SDK synchronously at the top of the preload. |
| Loader hooks | Node 26.8 and 22.23, import-in-the-middle 3.5 | `module.register()` is deprecated (DEP0205). ESM apps need the hooks in place before their import graph loads. `supportsSyncHooks()` is true from 22.22.3, 24.11.1 and 26. Without an `include` list the hook wraps every ESM module, the app's own files included (a re-parse and a namespace shim each, and a known source of circular-import errors). The instrumentations patch through the copy of import-in-the-middle that `@opentelemetry/instrumentation` depends on; a second copy registers hooks nobody uses. | Register with `module.registerHooks({ include })` when `supportsSyncHooks()` allows it, otherwise `module.register('import-in-the-middle/hook.mjs', import.meta.url, { data: { include } })`, as the first import of the preload. `include` names only the modules an instrumentation patches through ESM, for example `pg`, `http` and `https` (the `node:` forms are added); fetch needs none. Check `npm ls import-in-the-middle` shows one copy. Load the register module with `node --import`; a later import is too late for static imports. |
| Resource | sdk-node 0.222, resources 2.11 | By default `NodeSDK` adds `telemetry.sdk.*`, and its detectors add `host.*`, `os.*` and `process.*`. The `resource` option replaces the default resource, which drops `telemetry.sdk.*`; `resourceDetectors: [envDetector]` leaves only the environment detector, which drops `host.*`, `os.*` and `process.*`. | Pass `resource: resourceFromAttributes({})` and `resourceDetectors: [envDetector]`, so the resource is what the loader wrote to `OTEL_SERVICE_NAME` and `OTEL_RESOURCE_ATTRIBUTES`. |
| Express layer spans | instrumentation-express 0.70, Express 4.21 | `ignoreLayersType: [middleware, router, request_handler]` drops every layer span. The instrumentation then contributes only `http.route` on the SERVER span: the router's mount path for a request that falls through a router mounted on a prefix to the app's 404 handler, and nothing for a request rejected before routing. | Keep it as the source of the span's route, or leave it out and take the route in the module (row below). Either way, the 404 handler sets the RPC route to `unmatched` (`getRPCMetadata(context.active()).route`), so the span says `unmatched` like the metrics and the access log. |
| Express route template | Express 4.21 | `req.route` is set when a route matches, and at that moment `req.baseUrl` holds the router's mount path. By the time an error handler responds, `req.baseUrl` has been reset, so a template built at response time from `req.baseUrl` and `req.route.path` reads `/:id` instead of `/api/orders/:id`. A router's root route (`router.get('/')` mounted at `/api/orders`) joins to `/api/orders/`. | Capture the template when `req.route` is set, for example with a setter on `req.route` that the outermost middleware installs, strip a trailing `/` (`/api/orders`), and use it for the metrics and the access log, and for the span through the RPC route (`getRPCMetadata(context.active()).route`, read by the HTTP instrumentation at response end) when the Express instrumentation is left out. Set the RPC route to `unmatched` when the middleware starts, so a request rejected before routing (a 401 from a router-level auth middleware, a body-parser error) is `unmatched` too. |
| HTTP client metrics | instrumentation-http 0.222, instrumentation-undici 0.32 | Both instrumentations emit `http.client.request.duration` under their own scopes, so a Prometheus export of OpenTelemetry metrics showed the family twice. | Keep OTLP metric push off; the client metrics come from the Prometheus client library ([metrics](signals/metrics.md)). If the team switches push on, drop the instrumentations' HTTP metrics with a view. |
| Export calls in client metrics | sdk-node 0.222, core 2.11 | The SDK runs each export with tracing suppressed, sometimes from a timer that inherited a request's async context, so the export's own HTTP call sees an active span. | Count a client call only when a span is active and `isTracingSuppressed(context.active())` (from `@opentelemetry/core`) is false, so the SDK's own exports never reach the client metrics ([metrics](signals/metrics.md)). |
| Metrics library | `@prometheus-io/client` 0.16 | `prom-client` is deprecated and continues as `@prometheus-io/client`, with the same API (`Registry`, `collectDefaultMetrics`, `Counter`, `Gauge`, `Histogram`). | Install `@prometheus-io/client`. |
| Connection pool | pg 8 | `Pool` exposes `totalCount`, `idleCount` and `waitingCount`, but no wait time. | Read the three at scrape time. Time `connect()`, which `pool.query()` also uses, for `db_pool_wait_duration_seconds`. |
| Install scripts | npm 11.19 | Dependency install scripts are skipped by default (`npm install-scripts ls` lists them). `npm ci` also rejected a lockfile written by an older npm (optional peer dependencies missing from it), while `npm install` rewrote it. | Use packages that ship prebuilt native binaries (`@datadog/pprof`, bcrypt 6 and sharp do), and check them on the production image. Run the project's own install command; report a lockfile rewrite and the version changes in it. |
| SDK diagnostics | `sdk-node` 0.223 | No diagnostics logger is set unless `OTEL_LOG_LEVEL` is, and the loader removes stray `OTEL_*` variables: a failed export (collector down, wrong endpoint) is silent. The global error handler passes the error serialised as JSON (`{"message": …, "stack": …}`). | `diag.setLogger(…, DiagLogLevel.WARN)` in the preload with a logger that writes one JSON line to stderr per distinct message per minute, taking the message from the serialised error and never request content. |
| Uninstrumented clients | firebase-admin 13.10, nodemailer 10.0 | FCM sends over HTTP/2, which neither the http instrumentation nor Node's HTTP diagnostics channels cover; nodemailer speaks SMTP over a raw socket. Neither gets a span or a client metric. | Wrap each call in a CLIENT span with the peer name (`firebase-fcm messaging.sendEachForMulticast`, `smtp sendMail` with `server.address` and `server.port`). |
| Classes with static methods | TypeScript services and controllers | Routes take method references when they import the module (`asyncHandler(OrdersController.list)`), so a wrap applied later is missed. Some static methods are getters, fields (`static cache = new Map()`) or synchronous helpers; some return query builders that are thenables. | Wrap right after the class (`traceClass(Orders, 'Orders')`): only own native `async` functions, keeping each property descriptor, `name` and `length`, calling the original with the caller's `this`; await only real promises. Leave out middleware plumbing (token checks, permission lookups run on every request) and scheduler classes, whose runs are job spans. |
| Process signals | Node 22 and 26 as PID 1 | With no SIGTERM handler, Node as a container's PID 1 ignores SIGTERM, so the pod is killed at the end of the grace period with requests in flight. A handler keeps the process alive until the event loop empties, which intervals, cron tasks and keep-alive sockets prevent. An `unhandledRejection` or `uncaughtException` listener turns off Node's default crash. | On SIGTERM: stop the schedulers, `server.close()` with a drain deadline then `closeAllConnections()`, wait for running job runs, flush telemetry, close the pool, then `process.exit(0)`, all within the grace period; a second signal exits at once. The crash listeners write one FATAL record, flush (bounded) and `process.exit(1)`. Install them in the server entrypoint, never in a module tests import. |
| App logger | Node.js without a logger | Node has no standard logger. `@opentelemetry/instrumentation-pino` can't patch a pino the preload loads before its hooks, and pino writes straight to fd 1, past a test suite's `console` spies. | Either the project's logger, configured to the standard, or a small module logger: JSON lines on `process.stdout.write` with the exact keys and the active span's ids, a sink tests can replace, settings read from the config the preload resolved. Never a second logger next to an existing one. |
| Profiler | `@pyroscope/nodejs` 0.6.4 | Sends only bearer or basic auth and `X-Scope-OrgID`, has no OTLP output, and uploads heap profiles every 15 s with none at shutdown. Failed uploads are silent (its logger logs nothing by default). Pyroscope's span profiles don't cover Node.js: labels have no async context. | Send other auth through the collector. Link profiles to spans by adding the active span's `span_id` and `trace_id` next to `controller` in the heavy-section helper, which wraps synchronous code only ([profiling](signals/profiling.md#span-profiles)). |
| Profiler labels | `@pyroscope/nodejs` 0.6 | `wrapWithLabels` sets the label, runs the call and resets the label when the call returns. It uses @datadog/pprof without async context, so labels don't cross `await`: in uploaded profiles, samples after an `await` inside the labelled function had no `controller` label. | Wrap the CPU-heavy synchronous sections (parsing and conversion, regex redaction, serialisation), not whole async functions, and never an async job body ([profiling](signals/profiling.md#labels-per-runtime)). |
| Profiler series labels | `@pyroscope/nodejs` 0.6 | Adds its own `process.runtime.name`, `process.runtime.version` and `otel.scope.*` series labels next to the static tags. | Expected: they can't be dropped without patching the SDK, so leave them. |
| `fetch` | undici instrumentation 0.32 | Built-in `fetch` gets client spans and `traceparent` only through the undici instrumentation. | Enable it beside the http instrumentation. |
| NestJS instrumentation | `@nestjs/core` 12.1, `instrumentation-nestjs-core` 0.68 | The Nest instrumentation supports `@nestjs/core` below 12 only, and Nest 12 packages are ESM-only. Nest 12 offers a framework telemetry package (`@nestjs/observe`) and a JSON logger with redaction. | Evaluate the framework's own package first (leverage, then enforce). Otherwise use the Express and undici instrumentations and add function spans by hand. |
| NestJS routing | 12.1 | With a global prefix, paths outside it get Express's default 404 and skip Nest middleware, guards and filters. The full route template is on Express's `req.route.path`. | Install the access log at the HTTP-server level so unrouted requests are logged. |
| NestJS shutdown | 12.1 | `enableShutdownHooks()` runs `beforeApplicationShutdown`, then `onApplicationShutdown`, then re-raises the signal. | Flush telemetry in those hooks, within the deadline. |
| Next.js client start | Next.js 16.3 | `instrumentation-client.ts` runs after the HTML loads and before hydration; only its synchronous top-level code is sure to finish first (a dev warning flags more than 16 ms). `onRouterTransitionStart(url, navigationType)` reports client-side navigations; route patterns (`event.fromRoutes`) need an experimental flag. | Start the web SDK synchronously there; keep a route-pattern list in code for `app.route` ([fullstack](workloads/fullstack.md)). |
| Next.js build-time variables | Next.js 16 | `NEXT_PUBLIC_*` values are inlined into the client bundle at build time. | Serve RUM settings at runtime from the root layout; never put keys or per-environment values there. |
| Next.js middleware rename | Next.js 16 | `middleware.ts` is now `proxy.ts`; it runs before routing and can't see the response status. | Write the access log from the server root span instead. |
| Next.js built-in spans | Next.js 16.3.8 | Once a tracer provider is registered, Next renames the root span `{method} {route}` (for example `POST /api/orders/[id]`) with `http.route` and `error.type` on 5xx. Its patched `fetch` creates CLIENT spans named `fetch GET <full URL>` with the full URL, query included, in `http.url`. | Set `NEXT_OTEL_FETCH_DISABLED=1` and keep one client instrumentation (undici) with sanitised URLs and `{method} {url.template}` names. |
| Next.js module copies | Next.js 16.3.8 | `instrumentation.ts` gets its own copy of shared `lib` modules; route handlers share another. `next start` holds requests, `/health` included, until `register()` resolves. | Keep process-wide telemetry state (providers, metrics server, logger) on `globalThis` or start it in `register()`. |
| Next.js minification | Next.js 16.3.8 | Production server bundles mangle top-level function and class names; method names survive. | Set `code.function.name` explicitly in the wrappers; don't derive it from `fn.name`. |
| Next.js SIGTERM | Next.js 16.3.8 | `next start` closes the server and calls `process.exit(143)` on SIGTERM. | Set `NEXT_MANUAL_SIG_HANDLE=true` and flush telemetry in your own handler before exiting. |
| Next.js dev agent files | Next.js 16.3 | `next dev` writes `AGENTS.md` / `CLAUDE.md` into the project when it detects an AI agent, unless `agentRules: false`. | Don't run `next dev` in a project you only instrument, or set `agentRules: false`. |
| Next.js CLI telemetry | Next.js 16 | `next build` sends anonymous usage telemetry by default. | `NEXT_TELEMETRY_DISABLED=1` where builds must not call out. |
| React event-handler errors | React 19.3 | Errors thrown in event handlers go to `window.reportError`, which fires the window `error` event. | The `error` handler catches them; don't also wrap handlers, or the error is recorded twice. |
| OTel Web packages | sdk-trace-web 2.11, instrumentation-fetch 0.222, instrumentation-document-load 0.67 | Document-load spans record `location.href` and fetch spans the request URL, both with the query, in `url.full`. Exports to the page's own `/telemetry/` routes are traced too unless ignored. | Clean URL attributes before export; set `ignoreUrls: [/\/telemetry\//]` on the fetch instrumentation. |
| OTel logs SDK | sdk-logs 0.222 | `BatchLogRecordProcessor` takes an options object (`{exporter, scheduledDelayMillis}`); passing the exporter alone fails silently. | Pass the options object. |
| OTLP response bodies | `@opentelemetry/otlp-exporter-base` 0.223 (proto exporters), OneUptime 14.0.50, Langfuse 4.58 | The proto exporters decode the response body as protobuf. OneUptime and Langfuse answer `{}` as JSON, so the diagnostic logger warns `Unknown wire type 3, cannot safely skip` although the data was accepted. Diagnostic errors also carry the error object, whose serialisation includes a stack trace. | Treat that warning as harmless and drop it in the module's diagnostic logger, which writes an error's message only, never its stack. |

| Topic | Seen with | Behaviour | What to do |
| --- | --- | --- | --- |

| uvicorn | 0.54 | Re-raises SIGTERM after a graceful shutdown. | Flush in the lifespan shutdown, before the re-raise. |
| Span profiles | pyroscope-otel 1.1 with pyroscope-io 1.2 | `PyroscopeSpanProcessor` tags the OS thread with `span_id`, `span_name` and `trace_id` for each local root span. pyroscope-io sends pprof, so the tags arrive as sample labels; concurrent asyncio requests share a thread and get each other's labels. | Add it to the tracer provider when profiling is on, for threaded or pre-fork servers that run one request per thread at a time (gunicorn sync and gthread workers); never on asyncio. | Pre-fork servers | gunicorn with `--preload`, prometheus_client 0.26 | The app is imported in the master before the workers fork. prometheus_client's multiprocess mode (`PROMETHEUS_MULTIPROC_DIR`, a `MultiProcessCollector` on its own registry) merges the workers' metrics into one `/metrics`; that registry has no process or GC collectors. | Create providers in `post_fork`, never in the master. | Django instrumentation | Django 6.1, instrumentation-django 0.66b0 | `DjangoInstrumentor` inserts its middleware into `MIDDLEWARE`, so it must run before `get_wsgi_application()` builds the handler. A log handler added before `django.setup()` is removed when Django applies `LOGGING`. Routes have no leading slash (`api/orders/<str:order_id>`). `django.request` logs every 4xx and 5xx with the request's repr, query string included. | Instrument at the top of `wsgi.py`. | gunicorn control socket | gunicorn 26.2 | Since 25.1 the master starts a control socket at `~/.gunicorn/gunicorn.ctl`, served by a thread, so the master is no longer single-threaded at fork. | Turn it off in `gunicorn.conf.py` when the master must stay single-threaded. |
| gunicorn's own logs | gunicorn 26.2 | Its start-up, worker and error lines use gunicorn's own format unless `logconfig_dict` is set. gunicorn merges that dict over its defaults one level deep, so a dict without `root` keeps the default root logger, whose `console` handler no longer exists, and the master exits ("Unable to configure root logger"). | Set `logconfig_dict` in `gunicorn.conf.py` with the app's formatter on a stdout handler, `root` included, `gunicorn.error` on that handler and `gunicorn.access` silent (the access log is the app's). |
