# GitOps & Delivery Naming Conventions

This document specifies the exact naming conventions and derivation formulas used across GitOps repositories and CI/CD delivery pipelines for **ArgoCD** and **Komodo**.

---

## 1. Branch Naming Standard

Environment branches within GitOps repositories represent the combination of a product and an environment:
```
{product-name}/{environment}
```
Examples:
- `myapp/dev`
- `myapp/qa`
- `myapp/pre-prod`
- `myapp/prod`
- `acme/vpn`

### Environment Normalization & Alias Mapping
When users provide environment names, map aliases automatically:
- `dev` $\leftarrow$ `dev`, `development`, `develop`
- `qa` $\leftarrow$ `qa`, `test`, `testing`
- `staging` $\leftarrow$ `staging`, `stage`, `stg`
- `pre-prod` $\leftarrow$ `pre-prod`, `preprod`, `pre_prod`
- `prod` $\leftarrow$ `prod`, `production`

If a branch cannot be resolved via alias or similarity search, **HALT** and instruct the user to contact DevOps.

## 2. ArgoCD Application Naming Formulas

### 2.1. Root App-of-Apps Application
Created at the cluster level to watch the GitOps repository and synchronize child applications.

**Formula**:
```
{chartBase}-{environment}-root
```
- `{chartBase}`: Extracted from line 2 of the GitOps repository's root `Chart.yaml` (e.g., `acme-cloud-myapp`).
- `{environment}`: The canonical environment name (e.g., `dev`).
- `-root`: Constant suffix.

*Example*:
`acme-cloud-myapp-dev-root`

---

### 2.2. Child Helm Microservice Application
Generated dynamically by `tpl.argocd.applications` from `.Values.apps`.

**Formula**:
```
{chartBase}-{serviceName}-{environment}
```
- `{chartBase}`: Extracted from `Chart.yaml` (e.g., `acme-cloud-myapp`).
- `{serviceName}`: Microservice chart/sub-app key (e.g., `chat-frontend`).
- `{environment}`: Target environment (e.g., `dev`).

*Example*:
`acme-cloud-myapp-chat-frontend-dev`

> [!NOTE]
> When configuring CI/CD delivery for a Helm service, the pipeline needs to sync **both** the root app and the child app:
> ```yaml
> argocd_apps: acme-cloud-myapp-dev-root acme-cloud-myapp-chat-frontend-dev
> ```

---

### 2.3. Manifest-Based Application ("Extras")
Generated by `tpl.argocd.application.extras` from folders inside `extras/manifests/<service>/`.

**Formula**:
```
{chartBase}-extras-{environment}-{serviceName}
```
- `{chartBase}`: Derived from `Chart.yaml` (e.g., `acme-cloud-myapp`).
- `extras`: Constant segment.
- `{environment}`: Target environment (e.g., `dev`).
- `{serviceName}`: Subdirectory name under `extras/manifests/` (e.g., `clamav`).

*Example*:
`acme-cloud-myapp-extras-dev-clamav`

> [!IMPORTANT]
> Unlike Helm deployments, Manifest-based deployments sync **ONLY ONE** application in CI/CD:
> ```yaml
> argocd_apps: acme-cloud-myapp-extras-dev-clamav
> ```

---

## 3. Komodo Docker Compose Stack Naming

**Formula**:
```
{product-name}-{environment}
```
- `{product-name}`: Core product identifier (e.g., `myapp`).
- `{environment}`: Target environment (e.g., `dev`).

*Example*:
`myapp-dev`

---

## 4. Hostname & Route Naming

When services expose routes (Ingress or Gateway API HTTPRoute):

**Formula**:
```
{hostname-based-on-chart}.{environment}.{domain}
```
- `{hostname-based-on-chart}`: Derived from service or component name (e.g., `chat-frontend`, `docs`).
- `{environment}`: e.g., `dev`, `qa`. (Omitted in production if using apex/naked domain).
- `{domain}`: Base domain discovered from existing values (e.g., `contoso.com`).

*Examples*:
- Dev: `https://chat-frontend.dev.contoso.com`
- Prod: `https://chat-frontend.contoso.com` (or `https://chat.contoso.com`)
